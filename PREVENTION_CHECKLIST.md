# Чек-лист защиты от компрометации через интернет-доступные сервисы

**Класс документа:** Prevention Checklist  
**Версия:** 1.0  
**Дата:** 2026-01-08  

## Немедленные меры (0–7 дней)

- [ ] Закрыть уязвимости из CISA KEV на всех внешних сервисах.
- [ ] Убрать админ-интерфейсы из интернета.
- [ ] Включить MFA для всех привилегированных и сервисных учётных записей.
- [ ] Отозвать неиспользуемые OAuth-приложения.
- [ ] Ротировать все секреты, которые могли быть скомпрометированы.
- [ ] Убедиться, что EDR нельзя отключить локальными правами.

## Краткосрочные меры (7–30 дней)

- [ ] Внедрить WAF перед публичными сервисами.
- [ ] Настроить EASM для постоянного контроля внешней поверхности.
- [ ] Ввести обязательный review OAuth-приложений (ежемесячно).
- [ ] Сегментировать бэкап-инфраструктуру (отдельный домен/сегмент).
- [ ] Внедрить JIT/JEA для административного доступа.
- [ ] Настроить журналирование всех входов в арендатор.

## Среднесрочные меры (30–90 дней)

- [ ] Провести учения по ransomware без предварительного уведомления.
- [ ] Обновить план восстановления и проверить холодные бэкапы.
- [ ] Внедрить модель zero trust для сервисных аккаунтов.
- [ ] Настроить detection-engineering процесс с ежемесячной проверкой.
- [ ] Провести обучение ИТ и ИБ по реагированию на инциденты.

## Долгосрочные меры (90–365 дней)

- [ ] Построить единый каталог внешней поверхности и владельцев сервисов.
- [ ] Внедрить автоматическое виртуальное патчирование для критичных сервисов.
- [ ] Расширить поведенческую аналитику на веб-процессы и RMM.
- [ ] Включить в модель угроз AI-агентов и цепочки поставок.
- [ ] Регулярно пересматривать политику доступа к арендатору и облакам.
