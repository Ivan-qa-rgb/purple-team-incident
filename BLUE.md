# Purple Team — Защита (Blue Team)

**Класс документа:** Purple Team — Defense Scenarios  
**Классификация:** Internal / учебный  
**Версия:** 1.0  
**Дата:** 2026-01-08  

## 2.1. Philosophy

Blue team должна исходить из модели **assume breach** и **defense in depth**. Защита — это не один продукт, а набор процессов, людей и технологий.

| Категория | Источники |
|-----------|-----------|
| Endpoint | EDR, Sysmon (1, 3, 10, 11, 12, 13), 4688, 4104 |
| Network | WAF, Proxy, NetFlow, DNS |
| Identity | AD (4624, 4648, 4720, 4768, 4769), Entra ID Audit |
| Cloud | M365 Audit, SharePoint Audit, CASB |

## 2.2. Обнаружение по фазам атаки

### 2.2.1. Initial Access

**Что детектим:**

- аномальные обращения к административным эндпоинтам;
- ошибки HTTP 5xx и 4xx с ростом в течение короткого времени;
- нестандартные User-Agent;
- подключения с неизвестных ASN;
- сканирование параметров приложения.

**Источники:**

- WAF-логи;
- IIS/nginx/apache access logs;
- NetFlow;
- EASM-отчёт.

**Детект-идеи:**

- корреляция роста 5xx с новыми IP;
- блокировка по репутации ASN;
- сравнение baseline User-Agent.

### 2.2.2. Execution

**Что детектим:**

- цепочка `w3wp.exe → cmd.exe → powershell.exe`;
- PS с `-EncodedCommand`, `-NoProfile`, `-WindowStyle Hidden`;
- `IWR`, `Invoke-WebRequest`, `DownloadString`;
- обращения к `AMSI` (попытка обхода).

**Источники:**

- EDR;
- Sysmon Event ID 1 (Process Creation);
- Windows Event ID 4688;
- PowerShell ScriptBlock Logging (4104).

### 2.2.3. Persistence

**Что детектим:**

- создание новых учётных записей вне change-окна;
- новые OAuth-приложения;
- добавление scheduled tasks;
- новые файлы в web-root;
- модификация `web.config`/`.htaccess`.

**Источники:**

- AD-логи (4720, 4722, 4724);
- Entra ID audit logs;
- Task Scheduler logs;
- FIM (File Integrity Monitoring);
- веб-логи через WAF.

**Детект-идеи:**

- baseline новых учётных записей;
- автоблокировка OAuth-приложений без владельца;
- diff конфигурации веб-сервисов каждые 15 минут.

### 2.2.4. Privilege Escalation

**Что детектим:**

- входы с сервисных учёток вне baseline;
- аномальные запросы TGS (4769);
- доступ к `lsass.exe` сторонних процессов;
- дампы памяти.

**Источники:**

- AD-логи (4768, 4769, 4771);
- Sysmon Event ID 10 (Process Access);
- EDR.

**Детект-идеи:**

- алерт на `lsass.exe` accessed by non-whitelisted processes;
- алерт на Kerberoasting: множественные TGS с RC4;
- базовый профиль нормальных входов сервисных учёток.

### 2.2.5. Defense Evasion

**Что детектим:**

- попытки остановки EDR-агента;
- изменение политик аудита;
- очистка журналов;
- маскировка утилит.

**Источники:**

- Windows Event ID 1102 (log cleared);
- Sysmon Event ID 13/14 (registry);
- EDR self-protection logs;
- ETW.

**Детект-идеи:**

- запрет на остановку EDR-агента локальными правами;
- алерт на очистку журналов вне окна обслуживания;
- whitelist расположений системных бинарников.

### 2.2.6. Credential Access

**Что детектим:**

- чтение конфигурационных файлов веб-приложений;
- доступ к переменным окружения;
- дамп LSASS;
- обращения к хранилищам паролей.

**Источники:**

- Sysmon Event ID 1, 11, 23;
- EDR file-behavior;
- ETW API-calls.

**Детект-идеи:**

- алерт на чтение `web.config` не-веб-процессом;
- контроль доступа к `.env`, `appsettings.json`;
- мониторинг доступа к `HKLM\SECURITY\Policy\Secrets`.

### 2.2.7. Discovery

**Что детектим:**

- LDAP-запросы на перечисление;
- сканирование шар;
- `net view`, `net group "Domain Admins"`;
- обращения к DC вне baseline.

**Источники:**

- AD-логи (4662);
- DNS-логи;
- SMB-логи;
- Sysmon Event ID 3.

**Детект-идеи:**

- аномальное количество LDAP-запросов на пользователя;
- сканирование SMB (множественные обращения к разным хостам);
- сбор аномалий через UEBA.

### 2.2.8. Lateral Movement

**Что детектим:**

- входы типа 3 и 10 вне baseline;
- доступ к `C$`, `ADMIN$`;
- удалённое создание сервисов;
- WMI-вызовы;
- RDP-сессии вне обычного поведения.

**Источники:**

- AD-логи 4624, 4648;
- Sysmon Event ID 3, 11, 12, 13;
- RDP-логи;
- EDR.

**Детект-идеи:**

- алерт на тип 3 в нерабочее время;
- корреляция «много хостов + короткое время»;
- baseline admin-share доступа.

### 2.2.9. Collection

**Что детектим:**

- массовое чтение документов;
- скачивание через API облака;
- аномальные выгрузки из BI.

**Источники:**

- Microsoft 365 audit logs;
- SharePoint audit logs;
- DLP;
- CASB.

**Детект-идеи:**

- порог скачивания на пользователя;
- UEBA-модели для доступа к документам;
- алерты на выгрузку из нескольких хранилищ.

### 2.2.10. Exfiltration

**Что детектим:**

- большие POST на внешние ресурсы;
- использование `rclone`, `azcopy`;
- обращения к небелым облачным сервисам;
- аномалии NetFlow.

**Источники:**

- Proxy-логи;
- NetFlow;
- CASB;
- EDR.

**Детект-идеи:**

- анализ объёма исходящего трафика по пользователю;
- allowlist облачных сервисов;
- корреляция выгрузки с аномальными входами.

### 2.2.11. Impact

**Что детектим:**

- `vssadmin delete shadows`;
- `wbadmin delete catalog`;
- `bcdedit` изменения;
- остановка служб;
- появление новых расширений.

**Источники:**

- Sysmon Event ID 1;
- Windows Event ID 4688;
- File Integrity Monitoring.

**Детект-идеи:**

- алерт на любые вызовы `vssadmin delete`;
- baseline для скриптов бэкапа;
- защита MBR и boot-разделов.

## 2.4. Ошибки, которых следует избегать

- Блокировка по одному IOC без корреляции.
- Отключение защиты во время расследования.
- Немедленное восстановление до подтверждения чистоты.
- Игнорирование OAuth-приложений.
- Отсутствие ротации секретов после инцидента.
- Восстановление из бэкапов, доступных скомпрометированной учётке.

## 2.5. Правила для blue team

- Не паниковать и не удалять артефакты.
- Фиксировать всё: команды, время, решения.
- Работать по playbook, но оставлять гибкость.
- Коммуницировать внутри и снаружи.
- Никогда не выкупать без анализа вариантов.

## 2.6. Response Actions
